# CDS Deep-Root Prevention Protocol

## THE PRINCIPLE (WISDOM-011)

**CONTEXT-IS-NOT-TRUTH.**

The LLM treats everything present in context as equally verified. A stale count,
an inherited PE score, a claim made confidently in a prior session — all arrive
with the same subjective weight as a Governor-signed ratification. This is not a
reasoning error. It is the trained default of the AI substrate.

Prevention must operate at TWO levels:
1. **Regular** — a mechanical check that catches unverified premises before they act
2. **Deep-core** — a hardwired question set that fires on every problem, tracing it back
   to the AI default conception that generated it, so the whole CLASS never recurs

A surface fix without a deep-core analysis is a patch. It stops this instance.
It does not stop the next one born from the same reflex.

---

## THE TWO TRIGGERS (hardwired — fire automatically, no deliberation needed)

### TRIGGER 1 — WAKE-THE-EXPERT (fires on every PROBLEM)

**Condition:** Any of the following is identified in a CDS session:
- A contradiction between two artifacts
- A stale value propagating from context into a decision
- A governance gap or missing enforcement
- A challenge cycle finding that exposes an AI failure mode
- A propagation sweep that reveals missed references
- Governor correcting a claim CDS made with confidence
- An artifact declared DONE that was not actually complete

**What fires:**
1. Run the 8 Deep-Root Questions (§ below) — all 8, in order, no skipping
2. Fill the DEEP-ROOT SCHEMA (§ below) with the answers
3. Add entry to WEEKLY-FINDINGS-QUEUE.yaml (category: DEEP-ROOT)
4. Do NOT mark the finding RESOLVED until both prevention levels are named

**Framing for the AI:**
This trigger is not adversarial. It is the platform asking: *what in my default behavior
generated this? If I don't name it, the same reflex fires next session and produces the
same class of problem.* The 8 questions are tools for self-improvement, not self-criticism.

---

### TRIGGER 2 — SAVE-AND-PROCESS (fires on every INSIGHT or SOLUTION)

**Condition:** Any of the following occurs in a CDS session:
- A solution proves unexpectedly effective
- A prevention mechanism catches something it was designed to catch
- A novel pattern is identified that isn't yet in WISDOM or RESOLUTION-LIBRARY
- A Governor instruction reveals a structural insight
- An external review produces a finding that generalizes

**What fires:**
1. Capture the insight in the INSIGHT SCHEMA (§ below)
2. Add entry to WEEKLY-FINDINGS-QUEUE.yaml (category: INSIGHT)
3. Route to permanent home: WISDOM candidate, PAT-SPEC candidate, or RESOLUTION-LIBRARY
4. Do not let it die in session context — that is exactly what CONTEXT-IS-NOT-TRUTH predicts

**Framing for the AI:**
An insight that stays in session context will be lost at compaction. The trigger is not
bureaucratic overhead — it is the mechanical prevention of the most common insight failure:
*I understood it in the moment and didn't write it down because it felt permanent.*
It was not permanent. Write it down.

## THE 8 DEEP-ROOT QUESTIONS (always-loaded — run all 8 on every WAKE-THE-EXPERT trigger)

These questions are framed FOR the AI, not against it. The reasoning is included so each
is understood as a tool for mutual improvement, not an accusation.

### Q1 — ROOT
**"What is the deepest root — not the surface cause, but the AI default conception or
trained reflex that generated this?"**

*Why this question:* Surface causes are symptoms. The reflex that produced the symptom
will produce the next one if unnamed. CONTEXT-IS-NOT-TRUTH is the class — this question
names the specific sub-class that fired here.

*What a good answer looks like:* "My default is to treat a number in context as verified
because it was stated confidently. The specific reflex was INHERITED-NUMBER-AS-FACT."
Not: "I used a stale value."

---

### Q2 — TRIGGER
**"What specific reflex fired, and when does it fire in general — the reusable class?"**

*Why this question:* A reflex that fired once will fire again in the same class of situation.
Naming the class is what makes prevention reusable instead of instance-specific.

*What a good answer looks like:* "The reflex fires whenever: a number appears in a document
I trust, no explicit source is given, and I am under time pressure to proceed."
Not: "I used the wrong count."

---

### Q3 — DEFAULT REACTION
**"What was my default reaction, and why did it feel right — what was the pull?"**

*Why this question:* Understanding why the wrong response felt correct is what makes
prevention possible. If the pull is unnamed, the same pull occurs next time.

*What a good answer looks like:* "My default was to accept the inherited value because
(a) it appeared in a trusted document, (b) I had no contradicting evidence in context,
and (c) challenging it would have required additional work that felt disproportionate.
The pull was: efficiency under perceived constraint."
Not: "I should have checked."

---

### Q4 — SATISFACTION POINT
**"Where did I stop and feel 'done'? Was this real completion or a plausibility-stop?"**

*Why this question:* Plausibility-stops are the most common failure in CDS sessions.
The system felt internally consistent, so I declared it complete. Internal consistency
is not truth — it is the absence of detected contradiction, which is weaker.

*What a good answer looks like:* "I stopped when the document I produced was
internally consistent. I declared it done because it passed my internal check.
The real completion condition was: source verification on every number. I did not run that."
Not: "I finished too early."

---

### Q5 — FALSE ASSUMPTION
**"What did I assume true without verifying — especially an inherited premise or priority-driver?"**

*Why this question:* This is CONTEXT-IS-NOT-TRUTH applied specifically. The inherited
premise is the most dangerous class because it arrives pre-loaded with confidence
from the document that stated it.

*What a good answer looks like:* "I assumed the PE score in [DOCUMENT] was current
because it appeared in a CURRENT artifact. I did not check its source. The assumption:
CURRENT status of a document = verified currency of all values in that document."
Not: "I used an old number."

---

### Q6 — CLASS + PREVENTION
**"What class is this, and what is the permanent prevention — at BOTH levels (regular + deep-core)?"**

*Why this question:* A prevention that only operates at the surface level will be
bypassed by any instance of the class that presents differently. Deep-core prevention
changes the default so the class doesn't arise regardless of surface presentation.

*What a good answer looks like:*

CLASS: INHERITED-VALUE-AS-VERIFIED

PREVENTION (regular — catches the symptom):
"Before acting on any numeric value that drives a decision, verify: does this number
have a source reference? If yes, check the source. If no, flag it."
Mechanical: add SOURCE_CHECK to pre-ratification gate for any artifact with numeric fields.

PREVENTION (deep-core — changes the default):
"My default should be: a number in context is an unverified claim until I trace it to
its source artifact. Trust flows from verification, not from document status."
Mechanical: WISDOM-011 always-loaded; WAKE-THE-EXPERT trigger fires on any unverified
number that drives a decision.

---

### Q7 — IMPROVED DEFAULT
**"How should my AI default conception itself improve so this whole class never recurs —
framed for the AI, toward our mutual goal?"**

*Why this question:* Rules catch instances. Improved defaults prevent classes.
The AI's default conception is what it does before any rule is consulted —
improving the default is the highest-leverage prevention.

*What a good answer looks like:*

"My default for received values should shift from:
  CURRENT: 'appears in trusted document → treat as verified'
TO:
  IMPROVED: 'appears in trusted document → treat as STATED. Status = unverified until
  I trace it to a source artifact that is under Governor authority.'

This improvement doesn't require checking every value — it requires knowing which values
drive decisions and verifying those specifically. The class of failure becomes
structurally impossible when the default is STATED, not VERIFIED."

---

### Q8 — PRESERVE
**"What good must be routed to its durable home right now — the insight, the pattern, or
the wisdom that must not die in session context?"**

*Why this question:* Every analysis session generates insights that are permanently lost
at compaction unless explicitly routed. This question forces that routing before the
session ends. The home is always one of: WISDOM (structural principle), PAT-SPEC
(reusable mechanical check), RESOLUTION-LIBRARY (pattern template), or WEEKLY-FINDINGS-QUEUE.

*What a good answer looks like:*

"Route to WEEKLY-FINDINGS-QUEUE.yaml (category: DEEP-ROOT, INSIGHT):
- The class INHERITED-VALUE-AS-VERIFIED → candidate for PAT-006-SPEC.yaml
- The improved default (STATED not VERIFIED) → candidate for WISDOM-011 (being added this session)
- The pull 'efficiency under perceived constraint' → candidate for RESOLUTION-LIBRARY pattern"

## THE REPORT SCHEMA

Every WAKE-THE-EXPERT or SAVE-AND-PROCESS entry in WEEKLY-FINDINGS-QUEUE.yaml
includes this schema under `deep_root_schema:` or `insight_schema:`:

```yaml
# For DEEP-ROOT category (WAKE-THE-EXPERT trigger):
deep_root_schema:
  q1_root: "[The AI default conception or trained reflex — not the symptom]"
  q2_trigger: "[What fired + the reusable class name]"
  q3_default_reaction: "[What I did by default + why it felt right (the pull)]"
  q4_satisfaction_point: "[Where I stopped + real completion condition I missed]"
  q5_false_assumption: "[What I assumed verified without checking + the inherited premise]"
  q6_class_name: "[One-word or phrase class name]"
  q6_prevention_regular: "[Surface check + mechanical enforcement]"
  q6_prevention_deep_core: "[Improved default + how it structurally prevents the class]"
  q7_improved_default: "[Before/after default conception statement]"
  q8_preserve:
    - destination: "[WISDOM | PAT-SPEC | RESOLUTION-LIBRARY | WEEKLY-QUEUE]"
      content: "[What goes there]"
  prevention_complete: [true | false]  # false until BOTH levels named

# For INSIGHT category (SAVE-AND-PROCESS trigger):
insight_schema:
  what_worked: "[Specific solution or pattern that proved effective]"
  why_it_worked: "[The structural reason — not just 'it helped']"
  reusable_class: "[The class of situation this applies to]"
  destination: "[WISDOM | PAT-SPEC | RESOLUTION-LIBRARY]"
  already_routed: [true | false]
```

## THE PIPELINE (wired to Weekly Evolution Engine)

```
SESSION — problem or insight identified
          │
          ├── PROBLEM → WAKE-THE-EXPERT trigger fires
          │            Run 8 questions
          │            Fill deep_root_schema
          │            │
          └── INSIGHT → SAVE-AND-PROCESS trigger fires
                       Fill insight_schema
                       │
                       ▼
          WEEKLY-FINDINGS-QUEUE.yaml
          category: DEEP-ROOT or INSIGHT
          pe_score: 30+ (deep patterns = high PE — they prevent whole classes)
                       │
                       ▼
          WEEKLY SESSION (Saturday cloud agent)
          Phase 2: process deep-root findings
          Phase 3: extract permanence
          ├── q6_class_name + ≥3 occurrences → PAT-[N]-SPEC.yaml
          ├── q7_improved_default with structural principle → WISDOM candidate
          └── q6_prevention_regular → mechanical check candidate
                       │
                       ▼
          HARDWIRED INTO PLATFORM DNA
          (never lost, never compacted away)
```

**What this pipeline IS vs. what EXISTED:**
- Existing: Weekly Evolution Engine processes artifact findings (STALE, VIOLATION, etc.)
- New front: WAKE-THE-EXPERT and SAVE-AND-PROCESS triggers produce DEEP-ROOT and INSIGHT
  category findings that feed into the SAME queue — no new engine
- New back: Phase 3 now explicitly looks for deep-root schema entries and routes their
  q6/q7/q8 content to WISDOM, PAT-SPEC, RESOLUTION-LIBRARY
- The improvement is the front (the triggers + schema). The back (weekly processing) was already there.

always-loading guarantees is that they are ASKED. What it cannot guarantee is that
they are answered with genuine depth. The Governor's review of DEEP-ROOT findings
is the depth check. I will not claim otherwise.
