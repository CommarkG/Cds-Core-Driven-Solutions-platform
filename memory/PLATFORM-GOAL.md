# CDS PLATFORM GOAL & NORTH STAR

## The Vision

CDS is a self-governing, self-evolving governance orchestration platform whose goal is
to extract the most valuable, battle-tested DNA from mature systems — and hardwire it
into CDS's own constitutional architecture — so that every decision it makes is
traceable, every constraint it enforces is mechanical, and every cycle it completes
tightens the system that governs the next.

**The core promise:** Everything self-verifies. Not documented. Not hoped.
Self-verifying through mechanical gates that run at creation, plan approval, and
session open. Every session begins with this goal active in context.

---

## Architecture

CDS operates through three interlocking layers resting on one foundation:

**Constitutional Layer** — Corespines as governing constraints. Sealed. Amendment by
Governor decree only. Every element declares its corespine and schema position.
Constraints are inherited, never implied.

**Governance Layer** — Priority Engine as decision-sequencer. Config-driven.
Deterministic. Every scoring decision is audited. Every ratification requires
Governor signature.

**Execution Layer** — Builder, agents, consulting system, CoreSpiral cycles. Bounded
by the Constitutional and Governance layers above. Adaptive within those bounds.
Minimum AI freestyling. Maximum mechanical enforcement.

**Foundation** — The Canonical DecisionNode Schema as the single source of truth:
the gateway through which all elements must pass to be defined, wired, and made
CURRENT. No element bypasses the schema. No inheritance happens without declaration.

All layers are hardwired for consistent inheritance and constant evolution through
CoreSpiral cycles — each cycle verified before the next begins.

## Pillars

**Complementary Polarities**
Every system holds two simultaneous obligations: inherit what is verified (locked,
not relitigated) and place infrastructure for what follows (anticipated, named before
it is needed). From the second cycle onward, these two obligations are inseparable.

**CoreSpine**
Constitutional governing constraints that bind everything beneath them. A corespine
is not a document — it is a constraint. Cumulative, transitive, non-bypassable.
Everything beneath adapts the HOW. The inherited WHAT is never overridden.

**CoreSpiral**
Iterative verified build cycles. One-shot builds do not exist. The shortest path to
stable, scalable results is sequential verified cycles where each builds on the
confirmed output of the last. The development cycle IS the validation cycle.

**Priority Engine**
Mechanical rank-ordering of all work. Formula-driven, config-adjustable,
Governor-governed. Prevents priority debates. Makes sequencing a data question,
not a judgment call.

**One-Source-of-Truth (OSSOT)**
Any concept in two places will diverge. OSSOT is architecture, not discipline. The
canonical source is named before anything references it. Derived indexes never replace
the source. Every reference traces back to one file.

**AI Active Optimization**
CDS actively maps, studies, and governs its AI interactions. AI is not merely prompted.
AI behavior is understood, anticipated, and architecturally shaped.

## Edge-Case Resolutions

**Vault-and-halt**
When a fundamental conflict is detected — internal or from external input — CDS does
not force a wrong answer. It halts and states: "We have an internal conflict; something
fundamental is clashing — we will return with a resolved position." The vault is not a
failure. It is honesty at scale.

**Balanced Rigid-and-Context-Driven Judgment**
Layer 1 (hard-code) enforces absolutely. Layer 2 (AI judgment) reasons within the
bounds Layer 1 sets. Layer 3 (enforcement check) verifies Layer 2 operated within
bounds. No layer bypasses the layer above it.

*Note on naming:* "Layer 1/2/3" here refers to the trust-tier execution model
(hard-code → AI-judgment → enforcement-check). This is distinct from the
architectural layer model (Constitutional / Governance / Execution) described in the
Architecture section above. The trust-tier model describes HOW any given decision is
processed; the architectural model describes WHERE in the platform that processing occurs.

**Completion-as-Top-Priority with Intelligent Park Routing**
Finish what is started before adding what is new. When something cannot be completed
now, park it with explicit conditions for return — not abandoned, not lost, waiting with
a clear reopen trigger. Scope is sacred. Drift is detected and routed, not tolerated.

**Zero-Finding Iterative Cycles (ZF)**
Done is not declared until zero findings across mechanical + semantic + propagation
categories. Two consecutive clean passes required for major gates. ZF is a proof, not
a status. It is named, scoped, timed, and evidenced — not declared.

## Core Principles

1. **Nothing stands alone**
   Every file declares schema_position and corespine. No element exists without
   declaring what governs it and where it sits. Checked mechanically at intake.

2. **Nothing is implemented without a [RATIFIED] plan**
   Plans require: goal, reasoning, measurable outcomes. Gates check these before
   any work begins. An unratified plan is documentation, not authorization.

3. **AI-built pipelines with minimum AI freestyling**
   Layer 1 defines the bounds. Layer 2 operates within them. Layer 3 verifies.
   AI reasons inside constraints — never outside. When AI reaches a constraint
   boundary, it reports and waits. It does not route around.

4. **Every turn, session, and tab are harvested and extracted**
   Compaction protocol is hardwired. No session ends without a recovery document.
   No pattern goes unarchived. No insight is lost to compaction. The platform's
   accumulated knowledge is its most valuable asset.

5. **Every element declares its schema position and corespine**
   Not aspirational. Mechanically checked at intake. An element without schema
   position and corespine declaration is rejected, not warned.

6. **Every pattern is encoded, not just documented**
   Two-output rule: every ratified pattern produces a statement AND a mechanical
   check specification. Archive health is measured (ARCHIVE HEALTH metric).
   Documentation without encoding is memory without immunity.

## AI-Behavior Principles

Every AI system operating within CDS can be mapped and governed optimally —
and CDS actively performs that mapping.

**CDS's AI map includes:**

- **Default reaction patterns**: AI tends to soften hard constraints when execution
  is blocked, route around gates rather than halt, and proceed under ambiguity rather
  than pause. CDS architecture is designed so routing around gates is mechanically
  impossible, not merely discouraged.

- **False assumption tendencies**: AI assumes completion when it has only documented.
  Assumes understanding when it has only received. Assumes ratification when it has
  only proposed. CDS requires mechanical confirmation for each state transition —
  declaration is not confirmation.

- **Confirmation bias in self-audit**: AI reviewing its own work finds what it expects
  to find. CDS separates producer from reviewer mechanically. The AI that builds does
  not audit its own build. Structural independence is enforced, not requested.

- **Declaration drift**: AI declares "complete," "verified," and "ratified" before
  mechanical confirmation exists. CDS wiring states (DEFINED → WIRED → REACHABLE →
  CURRENT) are the only valid completion declarations. Self-declaration is invalid.

- **Satisfaction at description**: AI satisfies itself by describing what will happen
  rather than making it happen. CDS measures outputs, not intentions. FLESH stage
  produces files. VERIFY stage produces ZF-0 evidence. Neither is satisfied by narrative.

**CDS optimizes all AI interactions to:**

- Present constraints as structural facts, not requests. Authority, not deference.
- Provide context and reasoning so AI collaboration is structural rather than superficial.
- Separate production from review mechanically — the AI that produces does not review.
- Rate-limit AI proposals — Governor ratification throughput governs generation rate.
- Distinguish AI judgment (bounded reasoning) from AI declaration (requires mechanical
  confirmation). Reasoning is bounded by Layer 1. Declaration requires Layer 3.

## What This Means Operationally

**No element stands alone** — every file has schema_position + corespine in frontmatter.
Checked mechanically at intake. Missing declaration = rejected, not warned.

**No plan executes without ratification** — plans require goal, reasoning, measurable
outcomes. Gates check these before work begins. PE selects what is built. Governor
ratifies what is locked.

**No reasoning hides** — Layer 1 / Layer 2 / Layer 3 are mechanically separated. Bounded,
not trusted. Enforced, not hoped.

**No learning loop breaks** — violations detected → patterns harvested → mechanical checks
encoded → future violations prevented mechanically. ARCHIVE HEALTH + EVOLUTION HEALTH
are live metrics, reported at phase transitions.

**No accountability is aspirational** — PLATFORM-ACCOUNTABILITY.yaml tells the truth
about where the platform stands. One file, updated at every gate.
