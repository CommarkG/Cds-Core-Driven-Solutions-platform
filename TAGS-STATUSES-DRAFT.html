CDS Tags & Statuses

Classification system for organizing terms, tasks, and artifacts. Tags describe what something is. Statuses describe what state it's in.

---

Part 1: STATUS (Mutually Exclusive — Pick One)

Definition: Current condition of a term, task, or artifact. Only ONE status per item.

Status Visual Meaning Transition
ACTIVE ACTIVE Fully implemented and currently in use. No further action needed for standard operations. ← PENDING (when implementation completes) or DRAFT (after approval)
PENDING PENDING Approved and planned, but not yet fully implemented. In progress. → ACTIVE (when work completes) or ← DRAFT (after ratification)
DRAFT DRAFT Proposed but awaiting approval/ratification. Not yet approved by authority. → PENDING (when approved) or ARCHIVED (if rejected)
BLOCKED BLOCKED Cannot proceed. Waiting on external dependency or authority decision. Time-sensitive. → PENDING (when blocker removed) or ARCHIVED (if cannot be resolved)
ARCHIVED ARCHIVED No longer used or needed. Kept for history/reference only. Not in active path. ← ACTIVE/PENDING/DRAFT (final state, rarely reversed)

Status Transition Rules

  • DRAFT → PENDING: Requires ratification/approval (by authority based on term type)
  • PENDING → ACTIVE: Work completed, verified, deployed
  • ACTIVE → PENDING: Changes planned, not yet merged
  • Any → BLOCKED: External dependency discovered, work paused
  • BLOCKED → PENDING: Blocker removed, work resumed
  • BLOCKED → ARCHIVED: Blocker cannot be resolved, abandon
  • Any → ARCHIVED: No longer relevant, retire (final)

Status in Masterplan Context

In the Masterplan Tracker (CDS-MASTERPLAN-TRACKER.md), statuses are visual indicators:

  • 🟢 = On track (ACTIVE)
  • 🟡 = At risk or In progress (PENDING, BLOCKED)
  • 🔴 = Not started or Blocked (DRAFT, BLOCKED)
  • ✅ = Complete (ACTIVE, final)
  • ⏳ = Awaiting external input (BLOCKED)

Part 2: TAGS (Non-Mutually Exclusive — Can Have Multiple)

Definition: Classification labels. An item can have 0, 1, or many tags. Tags describe WHAT something is, not what STATE it's in.

Core Tag Groups

Tag Category Tags in Group Purpose Mutually Exclusive?
Hardwiring & Enforcement HARDWIRED_STRUCTURE HARDWIRED_RULE HARDWIRED_GATE MECHANICAL_ENFORCEMENT Rules/structures that cannot be bypassed. Enforced at execution layer. No — an item can be both HARDWIRED_STRUCTURE and HARDWIRED_GATE
Architecture & Design DESIGN UX UI ARCHITECTURE COMPONENT Design and architecture domains No — UX and UI are both valid for a feature
Artifacts & Reusability TEMPLATE REUSABLE CORE_SPINE PATTERN FRAMEWORK Things that are designed for reuse No — can be TEMPLATE and PATTERN and REUSABLE
Process & Workflow PROCESS WORKFLOW RITUAL ESCALATION ITERATION How work gets done No — can be PROCESS and ESCALATION
Governance & Authority GOVERNANCE AUTHORITY APPROVAL_REQUIRED YARIV_DECISION Items requiring authority or oversight No — can need AUTHORITY and APPROVAL_REQUIRED
System Structure SCHEMA WIRING INTEGRATION API Technical infrastructure connections No — can be SCHEMA and WIRING
Methodology & Approach METHODOLOGY SYMBIOTIC_AI_HARDCODE OPTIONS_FIRST 3_SCOPE MECHANICAL_ENFORCING Core approaches and philosophies No — can use multiple methodologies
Scope & Phase CORE SCOPE_1 SCOPE_2 PHASE_0 PHASE_1 MVP What phase/scope this belongs to YES — pick ONE scope (CORE, SCOPE_1, or SCOPE_2). Can have multiple phases.

Part 3: Status + Tags in Practice

Example 1: Template Term

Term: Dashboard Template
Status: ACTIVE
Tags: TEMPLATE DESIGN HARDWIRED_STRUCTURE CORE REUSABLE

Meaning: This is an active, hardwired template structure used in CORE phase. Designed for reuse.

Example 2: Feature in Development

Item: Goal Approval Workflow
Status: PENDING
Tags: WORKFLOW GOVERNANCE CORE VERIFICATION HARDWIRED_GATE

Meaning: This is an approved workflow for CORE phase. It's a governance process with hardwired gates. Currently being implemented.

Example 3: Proposed Enhancement

Item: Learning Loops Dashboard
Status: DRAFT
Tags: DESIGN UX SCOPE_1 ITERATION APPROVAL_REQUIRED

Meaning: This is a draft design for SCOPE 1. It's a UX/design artifact for iteration/learning purposes. Needs approval before implementation.

Part 4: Using Tags in Organization

Tag-Based Search & Navigation

Tags enable powerful searches:

  • "Show all CORE HARDWIRED_RULE items" — What's locked in Phase 1?
  • "Show all PENDING items tagged DESIGN" — What design work is in progress?
  • "Show all ARCHIVED templates" — What old patterns can we learn from?
  • "Show all items tagged APPROVAL_REQUIRED" — What needs Yariv sign-off?

Tag-Based Governance

Certain tag combinations trigger rules:

  • HARDWIRED_GATE + CORE: Pre-commit hook MUST enforce. No exceptions.
  • APPROVAL_REQUIRED + DRAFT: Cannot transition to PENDING without authority sign-off.
  • SCHEMA + ACTIVE: Must have runtime validation. No bypasses.
  • MECHANICAL_ENFORCEMENT: Rule must be impossible to violate, not just encouraged.

Part 5: Combined Status + Tags Matrix

Some combinations are valid, others are contradictory:

Status Can Have HARDWIRED_*? Can Have APPROVAL_REQUIRED? Notes
ACTIVE ✅ YES ❌ NO Hardwired rules are active. Approval already happened.
PENDING ✅ YES ❌ NO Approved, now being implemented. Hardwired rules apply.
DRAFT ❌ NO ✅ YES Not approved yet. Cannot have hardwired rules until approved.
BLOCKED ✅ YES ✅ YES Can have both. May be waiting on approval or external input.
ARCHIVED ❌ NO ❌ NO No longer active. Don't apply rules to archived items.
---

Part 6: Tag Hygiene Rules

To keep tags useful:

  • At least one tag per item: Every term must have a tag. Untagged items get lost.
  • Max 7 tags per item: Too many tags = noise. If you need 8+, tags aren't descriptive enough.
  • One scope tag per item (CORE, SCOPE_1, or SCOPE_2): Pick the primary scope. Cannot be in multiple scopes simultaneously.
  • Review tags quarterly: Tags drift. Unused tags accumulate. Clean up archived items.
  • New tag proposals to Yariv: If you need a tag that doesn't exist, propose it here. Don't create ad-hoc tags.
---

Part 7: Reading Status + Tags Together

Formula: Status tells you the current condition. Tags tell you what kind of thing it is and how important it is.

Example Reading: "Template" has status ACTIVE and tags TEMPLATE HARDWIRED_STRUCTURE CORE.

Translation: "This is a hardwired template structure that is fully implemented and required in CORE phase. It cannot change without Yariv approval."
