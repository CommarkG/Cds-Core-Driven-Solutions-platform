## THREE-AXIS CROSS MODEL DECISION (Governor input needed)

**Source:** CSPS ADR-0028

CSPS uses a three-axis cross model instead of a T-model:
- Axis 1 — Universal base: every artifact carries the same scaffold fields
- Axis 2 — Spine routing: routes into governance spines independently of domain
- Axis 3 — Domain extension: template adds domain-specific fields on top

**CDS analysis:** CDS already has all three axes — just not named that way:
- Axis 1 = the 14 common fields in CANONICAL-PLATFORM-ELEMENT-SCHEMA.yaml
- Axis 2 = `corespine_context` (routes to CS-PE-001, CS-GOAL-001, CS-THRESHOLD-001, etc.)
- Axis 3 = `element_type` (SYSTEM/DOMAIN) + `trunk_position`

**Key insight from CSPS:** "An ARCH artifact and a GVRN artifact can share the same
template while sitting in entirely different governance spines." This is exactly what
CDS's `corespine_context` field does — it cuts across the T-model independently.

**CDS recommendation: ADOPT the three-axis naming.**
Structural changes: NONE. The schema stays identical.
What changes: vocabulary. "T-model" becomes "three-axis cross model."
The field `element_type` becomes "Axis 3 (domain classification)."
The field `corespine_context` is formally named "Axis 2 (spine routing)."
The 14 common fields are formally named "Axis 1 (universal base)."

**This is a Governor decision. See PARKED-THREE-AXIS-DECISION.md for the full analysis.**
